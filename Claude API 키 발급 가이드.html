MICE 뉴스레터 운영

Claude API 키 발급 가이드

뉴스레터 자동화(RSS 수집, 기사 분석, 초안 생성)가 쓰는 Anthropic API 키를 어떤 종류로, 어떤 범위로 만들어야 하는지 정리한 문서입니다.

2026-10-12 작성 · 대상 서비스 mice-newsletter.vercel.app

요약

지금 막혀 있는 지점

현재 Vercel에 등록된 키는 sk-ant-usr- 로 시작하는 개인 키이고 범위가 조직으로 되어 있습니다. 이 조합은 모든 요청에 anthropic-workspace-id 헤더를 요구합니다. 뉴스레터 앱은 그 헤더를 보내지 않으므로 호출이 전부 거절됩니다.

해결 방법은 두 가지이고, 1번을 권장합니다.

방법내용코드 수정
1. 워크스페이스 범위로 재발급키를 만들 때 범위를 조직이 아니라 특정 워크스페이스로 지정합니다. 헤더 없이 바로 동작합니다.필요 없음
2. 조직 범위 유지 + 환경변수 추가Vercel에 ANTHROPIC_WORKSPACE_ID 를 함께 등록합니다. 앱이 헤더를 붙여 보냅니다.이미 반영됨
크레딧은 별개 문제입니다

키를 고쳐도 조직 크레딧 잔액이 0이면 credit balance is too low 오류로 다시 막힙니다. 크레딧은 워크스페이스가 아니라 조직 단위 지갑이고, 워크스페이스는 그 지갑에서 얼마까지 쓸지 나누는 칸막이입니다. 두 가지를 함께 확인하면 됩니다.

키 종류 이해하기

Console에서 키를 만들 때 연결된 계정과 범위를 고르게 되어 있습니다. 이 두 가지가 키의 성격을 결정합니다.

종류성격이 프로젝트 적합도
개인 키
sk-ant-usr-		 발급한 사람의 신원으로 동작합니다. 그 사람이 조직에서 빠지면 키도 같이 죽습니다. 개인 개발과 테스트용으로 적합합니다. 공용 운영에는 사람에 묶이는 약점이 있습니다.
서비스 계정 키 사람이 아니라 서비스 계정의 신원으로 동작합니다. 담당자 변경과 무관합니다. 운영 서버에 가장 적합합니다. 조직 관리자가 서비스 계정을 먼저 만들어야 합니다.
워크스페이스 키(레거시) 워크스페이스 자체에 속합니다. 지금도 동작하지만 신규 발급은 권장되지 않습니다. 새로 만들 이유는 없습니다.

Console의 "연결된 계정"에서 무엇을 고르나

키 생성 화면의 선택지는 세 가지로 보입니다. 각각이 위 표의 어느 종류에 해당하는지 정리하면 이렇습니다.

화면의 선택지결과판단
+ 서비스 계정 만들기 서비스 계정 키가 됩니다. 사람이 아니라 서비스의 신원으로 동작하므로 담당자가 바뀌어도 살아 있습니다. 이걸 고릅니다
GROUNDK (본인 계정) 개인 키가 됩니다. 지금 당장은 동작하지만 계정이 조직에서 빠지면 함께 정지됩니다. 차선책
연결되지 않음 (레거시 키) 구형 워크스페이스 키입니다. 아직 동작하지만 Anthropic이 신규 발급을 권하지 않습니다. 고르지 않습니다

서비스 계정을 새로 만들면 그 계정은 Default Workspace와 나중에 추가된 워크스페이스에만 접근할 수 있습니다. 전용 워크스페이스를 따로 만들었다면 Settings → Workspaces 에서 그 워크스페이스에 서비스 계정을 멤버로 추가한 다음 키를 발급합니다. 이 순서를 건너뛰면 키는 만들어져도 404 Workspace not found 가 납니다.

범위: 조직과 워크스페이스의 차이

범위요청할 때결과
워크스페이스키 하나로 해당 워크스페이스에서만 동작합니다. 추가 헤더가 없습니다.앱 수정 없이 바로 됩니다
조직여러 워크스페이스에 접근할 수 있어, 어느 워크스페이스로 과금할지 매 요청에 지정해야 합니다.헤더가 없으면 400 오류

즉 질문하신 대로 워크스페이스로 바꾸는 것이 맞습니다. 범위를 나중에 바꾸는 기능은 없으므로, 새 키를 만들고 기존 키를 삭제하는 식으로 교체합니다.

발급 절차

  1. 조직과 크레딧을 먼저 확인합니다

    Claude Console에 ops.mkt@groundk.com 으로 로그인한 뒤, 좌측 상단에서 GROUNDK 조직이 선택되어 있는지 봅니다. Billing 화면에 크레딧 잔액이 숫자로 떠야 합니다. 0이거나 표시가 없으면 키를 아무리 다시 만들어도 호출은 실패합니다.

  2. 워크스페이스를 정합니다

    Settings → Workspaces 에서 뉴스레터용 워크스페이스를 하나 정하거나 새로 만듭니다. 전용 워크스페이스를 쓰면 이 서비스가 쓴 비용만 따로 볼 수 있고, 월 한도도 따로 걸 수 있습니다. ID 열의 wrkspc_ 로 시작하는 값은 나중에 쓸 일이 있으니 적어 둡니다.

  3. 키를 만듭니다

    Settings → API keys → Create key 를 누르고 아래처럼 지정합니다.

    이름
    mice-newsletter-prod
    연결된 계정
    서비스 계정(권장) 또는 본인 계정
    범위
    워크스페이스 → 2단계에서 정한 워크스페이스
    만료
    Never 또는 1년 이상

    만료를 짧게 잡으면 그날 서비스가 멈춥니다. 현재 쓰는 키는 2026년 11월 11일에 만료되므로, 그대로 두면 그날부터 401 오류가 납니다.

  4. Vercel에 등록합니다

    Vercel 프로젝트 → Settings → Environment Variables 에서 ANTHROPIC_API_KEY 값을 새 키로 바꿉니다. Production에 체크되어 있는지 함께 확인합니다. 앞뒤 공백이나 따옴표가 섞이면 401이 나므로 값만 붙여 넣습니다.

  5. 다시 배포합니다

    Deployments 탭에서 최신 배포의 ... 메뉴 → Redeploy 를 누릅니다. 값만 저장하고 재배포하지 않으면 이전 키가 계속 쓰입니다. 서버가 켜질 때 만든 클라이언트를 재사용하기 때문입니다.

  6. 확인합니다

    관리자 화면의 RSS 페이지에서 수집을 한 번 돌리고, 후보 기사에 요약과 태그가 채워져 들어오는지 봅니다. 배포 전에 미리 키만 검증하려면 아래 스크립트를 씁니다.

키 검증 스크립트

키를 어디에도 저장하지 않고 한 번만 호출해 상태를 알려 주는 스크립트가 프로젝트에 들어 있습니다.

cd "C:\Users\akstn\OneDrive\바탕화~1-DESKTOP-G1P5I6M-334012\이우재\05. MICE Newsletter\01. Claude"
$env:ANTHROPIC_API_KEY = "새로 발급한 키"
node scripts/check-claude-key.mjs

조직 범위 키를 그대로 쓸 생각이면 워크스페이스 ID도 같이 넣어 확인할 수 있습니다.

$env:ANTHROPIC_WORKSPACE_ID = "wrkspc_..."
node scripts/check-claude-key.mjs

HTTP 200 정상입니다 가 나오면 그 키로 Vercel에 넣으면 됩니다.

오류 메시지별 대응

메시지원인조치
anthropic-workspace-id is required 조직 범위 개인 키인데 워크스페이스를 지정하지 않음 워크스페이스 범위로 재발급하거나 ANTHROPIC_WORKSPACE_ID 등록
credit balance is too low 키가 속한 조직의 크레딧 잔액이 0 Console Billing에서 충전. 키 문제가 아님
401 authentication_error 키가 잘못됐거나 만료, 또는 값이 잘려 들어감 값을 다시 붙여 넣고 재배포. 만료일 확인
404 Workspace not found 워크스페이스 ID가 틀렸거나 해당 계정에 접근 권한이 없음 Settings → Workspaces 에서 ID와 멤버 확인
ANTHROPIC_API_KEY is not configured 환경변수 이름 오타 또는 Production 미체크 Vercel 환경변수 이름과 적용 환경 확인
429 속도 제한 또는 워크스페이스 사용 한도 초과 잠시 후 재시도, 워크스페이스 월 한도 확인

운영 메모

  • 키는 사람에 묶이지 않는 서비스 계정 키로 두는 편이 안전합니다. 개인 키는 발급한 사람이 조직에서 빠지면 함께 정지됩니다.
  • 만료일을 길게 잡되, 달력에 갱신 일정을 남겨 둡니다. 만료된 키는 되살릴 수 없고 새로 만들어야 합니다.
  • 워크스페이스를 분리하면 이 서비스의 월 사용액만 따로 보이고, 실수로 과금이 튀는 상황도 한도로 막을 수 있습니다.
  • 로컬 개발용 키와 운영용 키는 분리합니다. 로컬은 .env.local, 운영은 Vercel 환경변수에 둡니다.
  • 앱이 쓰는 모델은 claude-haiku-4-5 입니다. 새 워크스페이스에서 모델 사용이 제한되어 있지 않은지도 한 번 볼 만합니다.
